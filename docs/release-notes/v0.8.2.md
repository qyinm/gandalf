# v0.8.2 Release Notes

Release title: `v0.8.2 - Selective Skill Profiles (boost) and Task-Based Injection`

## Summary

v0.8.2 introduces **`gandalf boost`** and **Task Profiles**, solving context bloat and tool hallucination across Claude Code, Cursor, and Codex. Teams can declare task-specific profiles (`[profiles.frontend]`, `[profiles.infra]`) in `gandalf.toml` and selectively inject skills into local agent runtimes via zero-latency relative symlinks.

## Highlights

- **`gandalf boost [profile]`**: Dynamically repoints agent skill paths (`.claude/skills/`, `.cursor/skills/`, `.codex/skills/`) using portable project-local relative symlinks (`../../.gandalf/skills/<name>`).
- **Context bloat & hallucination prevention**: Agents only load the exact skills required for the current task, conserving context window tokens and preventing accidental tool invocation.
- **Inheritance & DFS cycle detection**: Profiles support `includes` for clean composition with cycle detection.
- **Safety barrier**: Gandalf strictly refuses to overwrite or delete regular user directories or non-Gandalf symlinks (`ActionConflictSkip`).
- **Pruning & state management**: Switching profiles automatically prunes previous links and tracks state in `.gandalf/.boost.json` with self-healing recovery.
- **CI Drift Gate integration**: `gandalf check --ci` detects undeclared or missing skills referenced in profiles (`DriftInvalidProfile`), failing PRs before drift spreads.
- **Agent slash command templates**: `gandalf boost --setup-agents` generates native `/boost` commands for Claude Code and rules for Cursor.
